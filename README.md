# pokebox-ev — ポケモンカード BOX 開封期待値計算機

1BOX を開封したときに得られるカードの金額を、封入率と相場から計算する。
解析的な期待値（厳密解）に加えて、モンテカルロで **分布** も出す。

期待値だけを見ると必ず判断を誤る。BOX の価値は MUR や高額 SAR という
極端に低確率のカードが引き上げているため、分布は強く右に歪む。
「平均 4,084 円」の裏で「中央値 1,162 円」「元が取れる確率 6.8%」という
実態がある。この計算機は両方を並べて出す。

## 使い方

依存ライブラリなし（Python 3.10+）。

```bash
python3 -m pokebox_ev ev     data/abysseye_m5.json   # 期待値を計算
python3 -m pokebox_ev record data/abysseye_m5.json   # 今日の相場を履歴に記録
python3 -m pokebox_ev add    data/abysseye_m5.json --price 'SAR/ムク=3300'  # 1枚だけ更新
python3 -m pokebox_ev trend  data/abysseye_m5.json   # 期待値の推移を見る
```

`ev` の主なオプション:

| オプション | 説明 |
| --- | --- |
| `--mode kaitori\|hanbai\|both` | 買取価格ベース / 販売価格ベース / 両方（既定） |
| `--box-price 9800` | BOX 価格を上書きする（自分が買える値段で評価する） |
| `--trials 200000` | シミュレーション回数。`0` で解析値のみ |
| `--seed 0` | 乱数シード |
| `--cards` | カード単位の相場を出典・取得日つきで表示（数値の監査用） |
| `--json` | 結果を JSON で出力（他ツールに繋ぐとき） |

### 買取と販売を分ける理由

同じカードでも「ショップに売れる額（買取）」と「市場で買う額（販売）」は
2 倍前後ひらく。開封したカードを換金するつもりなら **買取**、
手元に残す価値を見るなら **販売** で評価する。世に出回っている
「BOX 期待値◯◯円」は多くが販売価格ベースなので、換金目的で読むと過大評価になる。

## 相場の推移を記録する

`data/history/<set_code>.jsonl` に **1 行 1 観測の追記専用**で貯める。
過去の記録は書き換えないので、あとから出典を検証できる。

```bash
# セット定義の相場をまるごと今日の観測として記録
python3 -m pokebox_ev record data/abysseye_m5.json

# 買取表から読んだ値を1枚ずつ入れる（こちらが日々の更新で使う口）
python3 -m pokebox_ev add data/abysseye_m5.json --date 2026-09-11 \
  --price 'SAR/メガダークライex=22000' \
  --price 'SAR/ムク=3300' \
  --source 'https://x.com/ttt_kaitori/status/...'
```

`add` は入力時にカード名をセット定義と照合するので、打ち間違いは弾かれる。

```bash
python3 -m pokebox_ev trend data/abysseye_m5.json --mode kaitori
```


観測が無い日は直近の値を持ち越す（forward fill）。毎日すべてのカードの
情報が出るわけではないため、これがないと系列が穴だらけになる。

## BOX 買取価格を毎日追う

期待値計算（カード単位）とは別系統で、`data/box_prices.jsonl` に
BOX の買取額をセット × 状態 × 店ごとに追記する。

### 毎日の流れ

1. トレカマサイ（[@ttt_kaitori](https://x.com/ttt_kaitori)）の買取表画像を
   `data/inbox/YYYY-MM-DD_ttt_kaitori.jpg` として置き、コミットする
2. 画像から数値を読み取って `box-add` で記録する
3. `box-trend` で前日比が出る

```bash
python3 -m pokebox_ev box-pending          # 未取り込みの画像を確認
python3 -m pokebox_ev box-add --date 2026-09-11 \
  --source '2026-09-11_ttt_kaitori.jpg' \
  --price 'アビスアイ/shrink=7000' \
  --price 'アビスアイ/noshrink=6300' \
  --price 'テラスタルフェス/carton=283000'
python3 -m pokebox_ev box-list             # 今日時点の全セット一覧
python3 -m pokebox_ev box-trend            # 推移と前日比
```

状態は `shrink`（シュリンク付き・既定）/ `noshrink` / `carton` / `other`。
同じセットでも状態と店が違えば別系列として持つ。

### 表記ゆれ対策

この用途で一番壊れやすいのは、同じセットが別表記で別系列に割れることだ
（アビスアイ / M5 / アビス）。`data/set_aliases.json` で正規名に寄せ、
**未知の名前は黙って通さない**。新しいセットは `--new` で明示的に登録する。

```bash
python3 -m pokebox_ev box-add --new --price '30th CELEBRATION/shrink=8000'
```

### 二重取り込みの防止

観測の `source` に画像のファイル名を入れているので、`box-pending` は
まだ `source` に現れていない画像を未処理として出す。別の状態ファイルを
持たずに済むが、**取り込み後も画像は消さないこと**。

### 自動収集の現状

実行環境の
[ネットワークポリシー](https://code.claude.com/docs/en/claude-code-on-the-web)
が x.com・cardrush-pokemon.jp・yuyu-tei.jp・snkrdunk.com を含む
カード関連サイトを全て遮断しているため、**買取表を自動で取りに行くことはできない。**
ツイートの画像を URL から取得する手段がなく、Web 検索が返すのは本文テキストのみ。

そのため入力は `data/inbox/` に置かれた画像を読む方式にしている。
画像さえ置かれていれば、その先（読み取り・記録・前日比の算出）は自動で回る。

## 計算モデル

期待値の線形性より

```
EV(BOX) = Σ_レアリティ (1BOXの期待枚数 × そのレアリティの平均相場) + バルク
```

枚数と単価が独立でなくても線形性は成り立つので、枠が「1枚 or 2枚」と
ブレても平均枚数さえ分かれば厳密な期待値が出る。

実際のパックは「この枠から1枚、この枠から1枚」という構造なので、
データ側も **枠（slot）** で表現する。

```jsonc
{
  "name": "SR以上枠",
  // 1BOXにこの枠が何回出るか
  "count": { "type": "discrete", "values": { "1": 0.65, "2": 0.35 } },
  // 引いたときの中身の内訳（合計1.0）
  "outcomes": [
    { "rarity": "MUR", "p": 0.0148 },
    { "rarity": "SAR", "p": 0.2089 },
    { "rarity": "SR",  "p": 0.7763 }
  ]
}
```

`count` は 3 種類:

- `{"type": "fixed", "n": 3}` — 必ず 3 枚（AR 枠など）
- `{"type": "bernoulli", "p": 0.02}` — 「50 BOX に 1 枚」なら `p = 1/50`
- `{"type": "discrete", "values": {"1": 0.65, "2": 0.35}}` — 任意の分布

レアリティ内では各種類が等確率に出ると仮定している（種類ごとの封入差は
公表されていないため）。相場が分からないカードは `count` でまとめられる:

```jsonc
{ "name": "その他SAR", "count": 4, "price": { "kaitori": 1500, "hanbai": 4000 },
  "estimated": true }
```

読み込み時に、内訳の確率合計・枚数分布の確率合計・レアリティ名の参照整合性を検証する。

## 別のセットを計算する

`data/_template.json` をコピーして数値を埋め、パスを渡すだけ。

```bash
cp data/_template.json data/mysets.json

```

## 同梱データセット

`data/abysseye_m5.json` — 拡張パック「アビスアイ」[M5] / 2026-05-22 発売。

### 相場の出どころ

買取価格は **X（Twitter）のショップ買取表ツイート** を一次情報にしている。
集計サイトの推定値ではなく、店が実際に提示した額なので信頼性が高い。
投稿日時はツイート ID（snowflake）から復元した。

| 出典 | 日付 | 取れた内容 |
| --- | --- | --- |
| [@toreca_rising](https://x.com/toreca_rising/status/2076538536778739977) | 2026-07-13 | MUR 1 種 + **SAR 全 6 種** + SR 3 種 |
| [@Machi_Modi](https://x.com/Machi_Modi/status/2075773936181399706) | 2026-07-11 | MUR 1 種 + SAR 4 種（上と照合用） |
| [@DCentGame](https://x.com/DCentGame/status/2057700265797759440) | 2026-05-22 | 初動買取表 |
| [@cardrush_poke](https://x.com/cardrush_poke/status/2057669038571188286) | 2026-05-22 | 初動買取表 |

重複する 4 種は 2 店で ±10% 以内に一致しており、相互検証が取れている。
`--cards` でカード 1 枚ごとの出典と取得日を確認できる。

### 前提と限界

- **買取データは 2026 年 7 月時点**で、2 か月ぶん古い。集計サイトの 9 月値では
  メガダークライex SAR が 22,000 円（7 月比 −30%）まで下がっているため、
  **実際の期待値はここで出る数字よりさらに低い可能性が高い。**
- **封入率はメーカー非公表。** すべて開封報告ベースの推定値。
  収録種類数は MUR 1 / SAR 6 / SR 18 / AR 12 / RR 8。
- 枠の根拠は「1BOX で RR 約 4 枚・AR 3 枚・SR 以上 1〜2 枚」という開封傾向の報告。
  SR 以上枠の内訳は、MUR = 50 BOX に 1 枚（0.02 枚/BOX）、
  SAR = 狙いの 1 種が約 4.7% × 6 種（0.282 枚/BOX）から逆算し、残りを SR に割り当てた。
- SR 以上枠の枚数分布 1 枚 65% / 2 枚 35% は平均 1.35 枚になるよう **仮置き**したもので、実測ではない。
  MEGA 期には「3 枚箱」パターンの存在が報告されているが、数値は取得できなかった。
- 販売価格は出典があるもの以外、買取 × 2.2 で推定している。
  とくに **ムク SAR は買取 4,200 円に対し販売 22,800 円**と開きが異常に大きく、
  `hanbai` モードの結果はこの 1 枚に強く影響される。買取ベースのほうが信頼できる。
- `"estimated": true`（`--cards` では `≈`）のカードは相場を取得できず推定で埋めた。
- 同一 BOX 内の重複は考慮していない（復元抽出）。1BOX あたりの枚数が
  種類数に比べて十分少ないため影響は小さい。
- BOX 価格は `--box-price` で自分が見ている値に上書きして使うこと。

# npb_pennant — NPB 優勝確率計算機

同じリポジトリに入っているもう 1 つの計算機。残り日程から**リーグ優勝の確率**を出す。

```bash
python3 -m npb_pennant                 # 既定データ（2026年セ・リーグ）で計算
python3 -m npb_pennant --sensitivity   # 仮定を変えた場合も並べる
python3 -m npb_pennant --assume WWL    # 直近3試合が勝勝負だった場合を反映
python3 -m npb_pennant --json          # 機械可読な出力
```

やっていることは 3 段階。

1. **実力をベイズ推定する。** 今の勝率をそのまま外挿しない。130 試合の勝敗には
   標準誤差 .044 の偶然が乗っており、そのまま使うと首位チームの確率は必ず過大に出る。
   Bradley–Terry モデル + 階層事前分布を MCMC で推定し、縮小した実力を使う。
   交流戦の負け越し（2026 年はセ 39 勝 65 敗 4 分）はパ・リーグを仮想チームとして
   分離し、セ内部の実力差と取り違えないようにしている。
2. **事後分布から強さを引き直しながら残り試合を再生する。** 点推定 1 つで回すと
   「実力自体がわからない」という不確かさが落ちて、確率が極端に出る。
3. **順位決定規定どおりに優勝チームを決める。** 勝率は勝/(勝+敗) で引き分けは
   分母に入らない。同率なら勝利数 → 当該球団間の対戦成績。引き分けが
   「勝率据え置きで残り試合を 1 つ減らす」＝リード側に有利、という非対称性も数える。

2026 年 9 月 20 日終了時点の結果（阪神 **52.3%** / 巨人 47.6% / DeNA 0.1%）と、
1 試合ごとの優勝確率・どの試合が優勝決定戦になるか・優勝が決まる日・感度分析は **[docs/PENNANT_2026.md](docs/PENNANT_2026.md)** にまとめてある。

入力データは `data/npb_2026_central.json`。各数値に `confirmed`（報道・公式で確認）/
`opponent_confirmed`（回戦数から対戦相手と試合数は確定、日付と球場は推定）/
`derived`（ゲーム差から導出）/ `estimated`（推定）の区別を持たせてある。
