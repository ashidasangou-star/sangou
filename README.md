# pokebox-ev — ポケモンカード BOX 開封期待値計算機

1BOX を開封したときに得られるカードの金額を、封入率と相場から計算する。
解析的な期待値（厳密解）に加えて、モンテカルロで **分布** も出す。

期待値だけを見ると必ず判断を誤る。BOX の価値は MUR や高額 SAR という
極端に低確率のカードが引き上げているため、分布は強く右に歪む。
「平均 4,084 円」の裏で「中央値 1,162 円」「元が取れる確率 6.8%」という
実態がある。この計算機は両方を並べて出す。

## 使い方

依存ライブラリなし（Python 3.10+）。

```bash
python3 -m pokebox_ev data/abysseye_m5.json
```

主なオプション:

| オプション | 説明 |
| --- | --- |
| `--mode kaitori\|hanbai\|both` | 買取価格ベース / 販売価格ベース / 両方（既定） |
| `--box-price 9800` | BOX 価格を上書きする（自分が買える値段で評価する） |
| `--trials 200000` | シミュレーション回数。`0` で解析値のみ |
| `--seed 0` | 乱数シード |
| `--cards` | カード単位の相場を出典・取得日つきで表示（数値の監査用） |
| `--json` | 結果を JSON で出力（他ツールに繋ぐとき） |

### 買取と販売を分ける理由

同じカードでも「ショップに売れる額（買取）」と「市場で買う額（販売）」は
2 倍前後ひらく。開封したカードを換金するつもりなら **買取**、
手元に残す価値を見るなら **販売** で評価する。世に出回っている
「BOX 期待値◯◯円」は多くが販売価格ベースなので、換金目的で読むと過大評価になる。

## 計算モデル

期待値の線形性より

```
EV(BOX) = Σ_レアリティ (1BOXの期待枚数 × そのレアリティの平均相場) + バルク
```

枚数と単価が独立でなくても線形性は成り立つので、枠が「1枚 or 2枚」と
ブレても平均枚数さえ分かれば厳密な期待値が出る。

実際のパックは「この枠から1枚、この枠から1枚」という構造なので、
データ側も **枠（slot）** で表現する。

```jsonc
{
  "name": "SR以上枠",
  // 1BOXにこの枠が何回出るか
  "count": { "type": "discrete", "values": { "1": 0.65, "2": 0.35 } },
  // 引いたときの中身の内訳（合計1.0）
  "outcomes": [
    { "rarity": "MUR", "p": 0.0148 },
    { "rarity": "SAR", "p": 0.2089 },
    { "rarity": "SR",  "p": 0.7763 }
  ]
}
```

`count` は 3 種類:

- `{"type": "fixed", "n": 3}` — 必ず 3 枚（AR 枠など）
- `{"type": "bernoulli", "p": 0.02}` — 「50 BOX に 1 枚」なら `p = 1/50`
- `{"type": "discrete", "values": {"1": 0.65, "2": 0.35}}` — 任意の分布

レアリティ内では各種類が等確率に出ると仮定している（種類ごとの封入差は
公表されていないため）。相場が分からないカードは `count` でまとめられる:

```jsonc
{ "name": "その他SAR", "count": 4, "price": { "kaitori": 1500, "hanbai": 4000 },
  "estimated": true }
```

読み込み時に、内訳の確率合計・枚数分布の確率合計・レアリティ名の参照整合性を検証する。

## 別のセットを計算する

`data/_template.json` をコピーして数値を埋め、パスを渡すだけ。

```bash
cp data/_template.json data/mysets.json
# 封入率と相場を埋める
python3 -m pokebox_ev data/mysets.json --mode kaitori
```

## 同梱データセット

`data/abysseye_m5.json` — 拡張パック「アビスアイ」[M5] / 2026-05-22 発売。

### 相場の出どころ

買取価格は **X（Twitter）のショップ買取表ツイート** を一次情報にしている。
集計サイトの推定値ではなく、店が実際に提示した額なので信頼性が高い。
投稿日時はツイート ID（snowflake）から復元した。

| 出典 | 日付 | 取れた内容 |
| --- | --- | --- |
| [@toreca_rising](https://x.com/toreca_rising/status/2076538536778739977) | 2026-07-13 | MUR 1 種 + **SAR 全 6 種** + SR 3 種 |
| [@Machi_Modi](https://x.com/Machi_Modi/status/2075773936181399706) | 2026-07-11 | MUR 1 種 + SAR 4 種（上と照合用） |
| [@DCentGame](https://x.com/DCentGame/status/2057700265797759440) | 2026-05-22 | 初動買取表 |
| [@cardrush_poke](https://x.com/cardrush_poke/status/2057669038571188286) | 2026-05-22 | 初動買取表 |

重複する 4 種は 2 店で ±10% 以内に一致しており、相互検証が取れている。
`--cards` でカード 1 枚ごとの出典と取得日を確認できる。

### 前提と限界

- **買取データは 2026 年 7 月時点**で、2 か月ぶん古い。集計サイトの 9 月値では
  メガダークライex SAR が 22,000 円（7 月比 −30%）まで下がっているため、
  **実際の期待値はここで出る数字よりさらに低い可能性が高い。**
- **封入率はメーカー非公表。** すべて開封報告ベースの推定値。
  収録種類数は MUR 1 / SAR 6 / SR 18 / AR 12 / RR 8。
- 枠の根拠は「1BOX で RR 約 4 枚・AR 3 枚・SR 以上 1〜2 枚」という開封傾向の報告。
  SR 以上枠の内訳は、MUR = 50 BOX に 1 枚（0.02 枚/BOX）、
  SAR = 狙いの 1 種が約 4.7% × 6 種（0.282 枚/BOX）から逆算し、残りを SR に割り当てた。
- SR 以上枠の枚数分布 1 枚 65% / 2 枚 35% は平均 1.35 枚になるよう **仮置き**したもので、実測ではない。
  MEGA 期には「3 枚箱」パターンの存在が報告されているが、数値は取得できなかった。
- 販売価格は出典があるもの以外、買取 × 2.2 で推定している。
  とくに **ムク SAR は買取 4,200 円に対し販売 22,800 円**と開きが異常に大きく、
  `hanbai` モードの結果はこの 1 枚に強く影響される。買取ベースのほうが信頼できる。
- `"estimated": true`（`--cards` では `≈`）のカードは相場を取得できず推定で埋めた。
- 同一 BOX 内の重複は考慮していない（復元抽出）。1BOX あたりの枚数が
  種類数に比べて十分少ないため影響は小さい。
- BOX 価格は `--box-price` で自分が見ている値に上書きして使うこと。

## テスト

```bash
python3 -m pytest tests/ -q
```

手計算できる小さなセットで解析値を検証し、シミュレーションの平均が
それに収束すること、同梱データセットの封入率が出典どおりであることを確認している。
