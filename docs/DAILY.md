# 日次の買取価格取り込み手順

毎日 22:00 JST に自動実行される。この文書がその手順書。

対象は **BOX の買取価格のみ**。シングルカードは追わない。
店は **トレカマサイ**（[@ttt_kaitori](https://x.com/ttt_kaitori)）。

## 手順

### 1. 未処理の画像を確認する

```bash
python3 -m pokebox_ev box-pending
```

未処理が無ければ**そこで終了**。ユーザーに報告もコミットも不要。
画像が置かれていない日は何も起きないのが正常な状態。

### 2. 画像を読む

各画像を Read ツールで開き、買取表の数値を読み取る。読み取るのは:

- セット名
- シュリンク付き / シュリンク無し / カートン の区別
- 買取額

**読めない項目は飛ばす。** 潰れて判読できない数字を推測で埋めてはいけない。
この記録は時系列の土台なので、誤った値が 1 つ入ると以降の前日比が全部狂う。
飛ばした項目は報告に書く。

### 3. 記録する

```bash
python3 -m pokebox_ev box-add \
  --date <画像の投稿日> \
  --source <画像のファイル名> \
  --price 'セット名/shrink=7000' \
  --price 'セット名/noshrink=6300'
```

- `--date` は**画像が投稿された日**（ファイル名の日付）。実行日ではない
- `--source` は画像のファイル名。これが二重取り込みの判定に使われる
- 状態の既定は `shrink`。`noshrink` / `carton` は明示する

セット名が未知だと弾かれる。**まず表記ゆれを疑い**、
`data/set_aliases.json` に別表記として追加する。本当に新セットのときだけ
`--new` を付ける。安易に `--new` を使うと系列が割れて台無しになる。

### 4. 差分を確認して報告する

`box-add` が前回比を自動で出す。加えて:

```bash
python3 -m pokebox_ev box-trend
```

### 5. コミットする

```bash
git add data/ && git commit && git push -u origin claude/pokemon-card-box-expected-value-o0o6wn
```

コンテナは毎回破棄されるので、**push しないと記録が消える**。

## 報告の内容

動きがあったときだけ簡潔に:

- 大きく動いたセット（前日比 ±5% 以上）
- 読み取れず飛ばした項目
- 新規に登録したセット

全セット横ばいなら「変動なし」の一行で十分。

## やってはいけないこと

- **判読できない数字を推測で埋める** — 飛ばして報告する
- **Web 検索で拾った数値で埋める** — 検索結果は要約であり数値が不正確。
  画像に写っている値だけを記録する
- **過去の記録を書き換える** — JSONL は追記専用。誤りは新しい観測で上書きする
- **取り込み済みの画像を消す** — `source` との突き合わせができなくなる

## 環境の制約

x.com・cardrush-pokemon.jp・yuyu-tei.jp・snkrdunk.com は
ネットワークポリシーで遮断されている。買取表を自動で取りに行くことはできないため、
`data/inbox/` に置かれた画像だけが入力源。
